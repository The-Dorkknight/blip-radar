Flash a real Blip node

Plug the board into this computer with a USB data cable, pick what you have, press Flash. It writes the firmware bundled with this release (after checking its checksum), or builds your own. Then join the board's Wi-Fi hotspot to use it.

⚠ EXPERIMENTAL — BRICK RISK

This writes third-party firmware to the HLK-LD2450 radar itself (not to the ESP32): earlynerd/HLK-LD2450_FW, MIT licence. It replaces the module's target reports with raw range-bin data streamed over the radar's own USB pins, for a PC viewer. While it is on, Blip's ESP32 cannot use that radar. Restoring stock has been done on its author's bench, but a failed write can leave a module needing recovery or dead. Use a spare radar. Nothing here is tested by Blip's author yet.

    It won't connect — what now?
    
      
      
    • Use a data USB cable. Charge-only cables show no port.
      • 
      
    • C3 Super Mini: hold BOOT, tap RESET, release BOOT, then press Flash. After a flash it comes back on a slightly different port; that is normal.
      • 
      
    • S3-Pico: hold BOOT while plugging it in. On Windows and older macOS it needs the CH343 driver (Waveshare wiki).
      • 
      
    • Linux: sudo usermod -aG dialout $USER, then log out and in (Arch: uucp). Without it the port exists but Blip may not open it.
      • 
      
    • macOS: the first run may ask to install the command-line tools (Git). Say yes.
      • 
      
    • Windows: close the Arduino IDE or any serial monitor, only one program can hold the port.
      • 
      
    • Quick flash downloads only esptool (about 40 MB) the first time. Build from source downloads PlatformIO and the ESP32 toolchain (a few GB) and needs Git; later builds are quick.
      • 
      
    • Want to flash without Blip? Quick flash shows the exact command; any ESP32 web flasher can also write the -full.bin at address 0x0.
      • 
      
    • Still stuck? Copy the log above and put it in a GitHub issue.
